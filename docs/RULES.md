# Pipeline rules catalogue (v59 – v79)

This is a catalogue of the deterministic rules the case-first pipeline applies, from v59 to v76b. Its readers are the
engineers who maintain the pipeline. Check it before you add a rule, so that you don't add one that already exists or
one that contradicts an existing rule.

## What a "rule" is here

A rule is a deterministic behaviour of the pipeline: a gate, a cap, an ordering, a status, a rewrite or a removal. The
code applies it in the same way to every case. Rules are tagged in comments and docstrings with the version that
introduced them (`v59`, `v60`, `v60b` … `v60t`, `v61` … `v76`, `v76b`). Sub-items are written `v60h (5)` or `v60f (P9)`:
the number or letter is the item of that version's change list. When a later version changes a rule, its tag stands
next to the older one in the same comment, for example "v60h … (v60t: gone …)". This catalogue lists each rule under
the version that introduced it and names the later amendments in the same bullet. Many entries in
`src/rag/interaction_copy.py` and `src/rag/writer_rules.py` are tagged "my draft". They are copy, which means fixed
wording for the parere or for the writer prompt, and they belong to the rules that use them.

Each bullet reads: what the rule does — version tag — `path:function`. A `function` can be a module constant or a data
file when that is where the rule lives. Several functions defined inside `src/rag/interactive_flow.py:_write_answer`
or `_reviewed` are cited by their enclosing function.

## Acceptance policy (from v77)

The 31 eval cases are **not** a measure for rules. They are listed in `tests/eval_narrative_cases.json`, and the ids
are `TUNING_IDS` and `HELDOUT_IDS` in `scripts/diagnose_long.py`. They are unit-test fixtures only:
`scripts/diagnose_long.py` is a diagnosis and runs no batch by default. A new rule is accepted on two things:

- **Structure and regressions:** the five-cell nightly, `scripts/nightly_sim.py`. It runs one case per posture cell:
  civile/attore/pre_filing, civile/convenuto/primo_grado, penale/imputato/primo_grado, penale/persona_offesa/pre_filing
  and lavoro/attore/pre_filing. For each cell it checks the intake, the parere's structure
  (`lawyer_method.structure_checks`) and the version footer. A check that passed yesterday and fails today is a
  regression.
- **Substance:** the lawyer's scores on the held-out set. The set is defined in `src/chatbot/heldout.py`. The pack is
  exported with `scripts/heldout_export.py` and scored with `scripts/heldout_score.py`.

v77 itself adds no pipeline rule. It covers delivery and measurement only: the `VERSION` file and `src/version.py`,
the «SunnitAI <version>» footer, `GET /api/version`, saving to the held-out set, and the acceptance change above.

No `v60a` tag appears anywhere in `src/` or `data/`.

- An atto requested on a narrated case is drafted with the case-first first read as its context (`case_record`) — v61 — `src/chatbot/api.py:_run_generation_sync`, `src/rag/document_generation.py:generate_document`

- The questions the message lists after a lead-in («si chiede di valutare: 1. … 2. …») each become a «quesito» block, in the message's order — v65 — `src/rag/intake.py:quesiti`

### 11.5 v79.11 (`ELEMENT_SCHEMAS`)

Element schemas: what an article requires, element by element, made once from its text and reviewed by the lawyer. With the flag off, nothing below runs, and every output, status, candidate, log line and existing counter is as in v79.9. With it on, an article without a usable schema runs the text path unchanged.

- **The schema.** One line per article in `data/article_schemas.jsonl`, made by `scripts/article_cards_bulk.py --schemas`. It holds:
  - the article's tipo (claim-conferring, defence, scriminante, limiting, definitional, procedural, sanction, other);
  - who it binds, who may invoke it and who suffers the conduct, each with an optional condition;
  - the rapporto;
  - the elements, each with its kind, comma, branches, connective and parts, and its grounding with the text passage;
  - the logic tree joining the elements, the eccezioni, the conseguenza, the special commi and the collegati.

  The code checks every line against the article's text: invalid structure, ungrounded explicit elements, fragments, branches with no «o» in the text, logic errors. A line with a blocking check is never used. Since v79.12.2 only an invalid schema and a logic tree with a dangling reference block; an ungrounded element (its content words not all in the text by Italian stem, function words ignored -- never a polarity word: non, senza, salvo, più/meno, dopo/entro, sopra/sotto), a fragment and branches with no «o» are fixed or dropped one by one and the schema is kept, the drop logged; a logic node with no args is removed and an empty tree is no logic (`scripts/schema_show.py --recheck` re-runs the checks over the existing file, `--unusable N` lists the rejected). Since v79.12.3 the checker first maps the vocabulary's synonyms (`data/schema_vocabulary.json`: «procedural» to «procedibilità» when the element speaks of querela or d'ufficio, else «competenza»; «evento dannoso» to «evento»; «ovvero», «oppure», «od» to «o»; «ed» to «e»; case, accent and plural ignored) instead of marking the schema invalid, each mapping logged; a value no synonym maps is still invalid. An element dropped takes every logic ref to it with it, and an all_of or any_of left with one child becomes that child, so the checker never leaves a dangling ref; one the model wrote still blocks. *Since v79.12.5 (item 0):* a conditional's if / then / else are pruned as args, the node collapsed or dropped, never left with a branch missing; «obbligo» is a condotta, a comma speciale's «limiting» a «limite», a logic op «other» lifted; a missing tipo is «other» with the note «tipo mancante», not invalid; `--recheck` counts every value no vocabulary maps, by field and value, and such a value is no longer a rejection: it is read as its field's neutral value (kind «other» with a note, tipo «other» with «tipo sconosciuto», role «altro», special kind «other», no connective, an op lifted), logged as a mapping; a non-string value stays invalid. «con», «senza», «contro», «salvo», «tranne» and «eccetto» are content words, and each must stand before the same word in the text, so «con il consenso» never grounds against «senza il consenso». The lawyer's overlay, `data/article_schemas_reviewed.jsonl` (`scripts/schema_show.py --edit`), wins while its source hash is the article's; a stale one sends the article to the text path. Since v79.12.3 the procedibilità (querela, d'ufficio, the conditions of either, an irrevocable querela, the querela's own term) is no element of the offence. It sits in the schema's «procedibilita» block, and the checker moves every element of kind «procedibilità» there (a mapped synonym too), along with any comma speciale of that kind, pruning their logic refs. The offence's logic then holds only the fattispecie. — `element_schemas.check`, `repair`, `prune_logic`, `stem`, `split_procedibilita`, `for_row`.
- **Decomposition.** An article whose row has a usable schema, of the same raw-text hash, gets the schema's elements in place of the text split. Their shape is `_requisites`' own (`"split": "schema"`, plus `schema_kind`, `schema_connective`, `schema_parti`, `schema_id`, `schema_grounding`). A fragment is still dropped. Kinds quantificazione, competenza and onere della prova are no requisites. *Since 79.12.3 neither is the procedibilità: it is the schema's block, read into the procedural store's procedibilità, and its d'ufficio conditions are the record's «procedibilita» entries (never a requisite and never part of the verdict).* A schema giving no element leaves the text path. Every decomposed record carries `element_path` {path: schema | reviewed | text, why}, and with a schema `rec["schema"]` (its summary: tipo, roles, rapporto, logic, reviewed). They are logged as `element_path` and kept in `state["element_paths"]`. — `issue_records._requisites`, `element_path`; `interactive_flow.decompose_records`.
- **General-part gate.** A schema's tipo joins the v74 gate at all three sites (build, decompose_records, method_records):
  - A sanction, claim-conferring, defence or scriminante tipo decomposes the article. The hard invariants stay: a procedural code's article, the general provisions, and c.p. Libro I other than 50-54 are never decomposed by a schema.
  - A tipo only limiting, definitional, procedural or other gates an article out only when the schema is reviewed. An unreviewed one never gates out what the current gate admits.
  - Disagreements are logged as `schema_gate_disagree`.

  — `issue_records.decomposed_by_gate(..., schema=)`, `element_schemas.decide`.
- **Grading.** One selector, `element_rule`, chooses the check for settle, polarity and the counters. It returns mental, duty, condition, termine, branches or plain. With no schema key on the element, it selects exactly what v79.9's regexes did.
  - A schema «elemento soggettivo» is a mental element too, so 79.9-A applies even when the text has no mental word. The union holds both ways: the regex still applies under any kind.
  - A «condizione» joined by «e» gets the 79.8-C3 per-part check, on its parts. A requisito gets it too. Half proven is «da provare», naming the missing part.

This stands in for 79.10-D1. *Replaced in 79.10.4 (D1): every element stating a term is graded on the facts' durations, the text path too; the stand-in's check stays only for a schema «termine» whose text states no duration; see 11.10.*

### 11.12 79.13.0 (`APPLICABILITY_FIT`: the applicability judgment)

Behind `APPLICABILITY_FIT` (default off; off, nothing runs and the output is 79.12.7's). The tables, the word lists and
the prompt are `data/applicability.json`; the module is `src/rag/applicability.py`. The model decides fit; it adds
nothing: every word of its judgment is checked by code before it has any effect.

- **The call.** The admitted candidates in balanced batches of at most 8 per call (`batch_size`; 30 = 8, 8, 7, 7), up to
  `concurrency` (4) calls at once, thinking off (`chat_template_kwargs.enable_thinking = false`), temperature 0, a JSON
  reply, through the repo's chat model (`ai_chat.chat_model`, the env's `LLM_*` config). Per norm: its full text and
  rubrica, its commi numbered («[1] …», `element_schemas.commi`), and -- with `ELEMENT_SCHEMAS` on -- the schema's tipo
  and rapporto labelled «solo contesto, non il giudizio»; once per call the facts (each with its id, labelled «certo»
  when accertato, else «allegazione») and the client's role. The system prompt is hashed (`prompt_hash`) and the hash
  logged with each run (`applicability_fit`). The reply per norm: `fit` si / no / dipende; `perche` one sentence quoting
  the article's passage in «» and naming the facts by id; `condizione` (dipende only) a question to the user; `ambito`
  fattispecie / scriminante / circostanza / rimedio / procedura / definizione.
- **Matching the reply** (`_match`, review). An item is the norm's by its label as `element_schemas.norm_label` reads
  it, or by number and code however spelt (`article_key`: «Art. 1819 c.c.», «articolo 1819 c.c.», «1819 cc», «1819
  c.c. (Restituzione rateale)»), or by its number alone when one norm of the batch has it and the code does not name
  another one. Two items for the same norm with different fits contradict each other: the norm unjudged («giudizi
  contrastanti», `fit_unverified`); the same fit twice: the first.
- **Failures.** A call that fails, a reply that is no JSON, a norm the reply leaves out, a value outside the schema: that
  norm unjudged (`fit_unverified`, logged), never a crash. A batch not back within `deadline_s` (20 s from the step's
  start) is not waited for (`fit_timeouts`): its norms keep the current path; a batch still queued then is cancelled
  (review: it never calls the model after the step gave up). A norm with no text, or a case with no
  facts, is not sent (`fit_skipped`).
- **The verification** (`applicability.verify`, no model). A judgment is discarded -- the norm keeps the current path,
  the reason logged (`applicability_fit_discard`) -- unless:
  (a) every quoted passage occurs in the article's text word by word in order (`passage_found`, `_align`): each content
  word as the schema checker grounds it (`element_schemas`' stem and verb base), and exactly -- never by stem -- a
  short word, a number, a function word, a polarity preposition and «non» (review: «50.000» for «2.000», «e» for «o»,
  «da sé» for «a sé» are not the text); the text's articles and simple prepositions (`omittable_words`) may be left
  out of the quote, the quote's own articles (`article_words`) added, nothing else skipped; and no negation
  (`negation_words`, behind at most two `negation_aux`) stands just before it in the text («è punibile» out of «non è
  punibile», «adempie l'obbligo» out of «non adempie l'obbligo» say the opposite: not found); a passage with no
  content word is never found;
  (b) it names at least one fact id, and every id named is a fact given;
  (c) its other content words (the quotes, the fact ids and the norm's own «art. N» out; function words and the data's
  `connective_words` aside) are each in the quoted passage, the named facts' text or the norm's reviewed note (the
  lawyer's note, `article_notes.for_label`; a reviewed schema's notes and elements), by the same stem grounding, and
  every number is one of theirs -- else it is also counted `fit_added_content` («richiede almeno tre persone» against
  a text that does not say it; another article's number; the norm's own reference is stripped only with its own code
  or none: «art. 646 c.c.» on 646 c.p. is another norm). `connective_words` carry no rule: «solo», «soltanto»,
  «richiede», «presuppone» are not among them (review); auxiliaries and plain words («hanno», «aveva», «parti»,
  «cioè», «conta») are. A word of the article outside the quoted passage is not grounding: the brief grounds the
  perché in the passage;
  (c2) a «no» or a «dipende» rests on the quoted passage (`_rests_on_passage`, review): a quantity word
  (`quantity_words`: «due», «almeno», «solo», «oltre» …) outside the quotes only as the passage's own -- else
  `fit_added_content` («La «rissa» non sussiste tra due persone (S1)»: the count is a rule the text does not set); the
  passage holds a word beyond `generic_norm_words` («Chiunque», «è punito» decide nothing); and a «no» quotes a
  requirement the named facts do not state, says what the facts are (a word of theirs outside the quotes) and that
  they lack it (a `negation_words` word) -- ««…» non riguarda (S1)» is no judgment;
  (c3) the perché never contradicts a named fact (`contradicted`, review): a word the facts hold only with the other
  polarity («non ha versato» against «ha versato»; a negation within three words of its clause);
  (d) with dipende, the condizione ends with «?» and its content words are in the article's text (any comma), the facts
  or the data's `question_words`, and a quantity word in it is the quoted passage's (review: «Alla rissa ha partecipato
  anche altri, non solo Tizio e Caio?» smuggles a count) -- else also `fit_added_content`;
  and the perché is one sentence. (e) A verified condizione's touched elements (`touches`: the norm's elements, else its

### 11.13 79.14.0 (`CASE_FRAME`: the case frame and its binding)

Behind `CASE_FRAME` (default off; off, nothing runs and the output is 79.13.0's). The tables, the vocabularies and the
prompt are `data/case_frame.json`; the module is `src/rag/case_frame.py`. One model call reads the case frame from the
request's full text; the code verifies every field against the text before it counts and never overrides a verified
field with a regex. Intake's and posture's rules are the fallback for a field the model leaves empty or that fails
verification; the verified frame is bound across the whole pipeline (below, «The binding»). Not
`CASE_FRAME_ENABLED` (the older frame of `defensive_generation._case_frame`).

- **The call** (`case_frame.read`). One call through the repo's chat model (`ai_chat.chat_model`, the env's `LLM_*`
  config), thinking off (`chat_template_kwargs.enable_thinking = false`), temperature 0, a JSON reply, the request's
  full text (cut only past `max_text_chars`, logged), within `deadline_s` (15 s: the brief's budget). The system prompt
  is hashed (`prompt_hash`) and logged with each run (`case_frame_read`). The reply: `parti` [{nome, ruolo_nel_fatto,
  lato cliente / controparte / terzo / autorità}], `cliente` {nome, perche}, `ruolo` {valore attore / convenuto /
  imputato/indagato / persona_offesa / ricorrente / resistente / sconosciuto, perche}, `rito` {valore: intake's riti,
  perche}, `stadio` {valore pre_filing / indagini / primo_grado / appello / cassazione / esecuzione / sconosciuto,
  perche}, `addebito_o_domanda` {articolo or null, descrizione, frase}, `istituto` {testo, frase}, `quesiti` (verbatim,
  in order). Each value maps onto intake's own vocabulary by the data (`ruoli`, `riti`, `stadi`: imputato/indagato ->
  imputato, ricorrente -> attore, resistente -> convenuto, appello / cassazione -> impugnazione; the spellings a model
  may use in `*_sinonimi`); a verified value carries both (`valore`, `intake`).
- **Failures.** A call that fails, a reply that is no JSON object, a call not back in 15 s: the whole frame empty,
  every field to the fallback (`frame_failed`), logged, never a crash. A field of the wrong shape: that field alone
  dropped.
- **The verification** (`case_frame.verify`, no model). Every quote is matched as the 79.13 fit checker matches a
  passage (`applicability.passage_at`, the match `passage_found` reads: word by word, content words by stem, numbers,
  short words and «non» exactly, never just after a negation of the text). A perché or a frase: its «…» passages each
  in the text, or with no quote marks the whole of it. A name (a party's, the client's) is matched exactly, never by
  stem (`name_found`: its words one after the other, accents folded, the data's `name_titles` aside, the company forms
  of `company_forms` written one way -- «Mario Rossi» is not «Maria Rossi», «Orsa Srl» is «Orsa S.r.l.»). `parti`:
  each name in the text and its lato in the vocabulary, else that party dropped (an off-schema lato that says
  controparte -- `controparte_words` -- still counts as controparte for the client rule); a ruolo_nel_fatto with a
  content word not in the text blanked. `cliente`: one only; a quote found (none: never accepted); its name in the
  text; never a party the reply lists as controparte; never another listed party than the one the user says they
  assist («assisto X», `interactive_flow.stated`); a quote naming another listed party and not the client refused; a
  name its own quote names only after one of the data's `counterparty_markers` («quali reati a carico di X»: X is
  whom the questions are about) refused, unless the text signals that the lawyer assists or defends that party
  (`client_signals` within `client_signal_window` words of the name, no marker between: «a carico di X, che mi ha
  chiesto di difenderlo»); a quote that is only the client's name refused; one of the verified parties with lato
  cliente. A client refused on its sides (listed as controparte, contradicting «assisto X», a quote showing another
  party, the «a carico» subject, a party of another lato) takes the reply's ruolo with it (`frame_unverified.ruolo`:
  the role is the refused client's). `ruolo` / `rito` / `stadio`:
  a vocabulary value and its quote found (none: never accepted); «sconosciuto» with its quote found is a verified value
  (`role_unknown`: the honesty line, neither side's wording), with no quote the field is empty and falls back.
  `addebito_o_domanda`: its frase found; a descrizione with words not in the text blanked; in a penal rito (the
  frame's -- a verified «sconosciuto» is none --, else the fallback's `rito_hint`) its articolo a penal provision
  (`is_penal`: the c.p.; the civil code's reati societari, 2621-2642 c.c.; a penal law's penal articles,
  `penal_provisions.laws` -- each law by its own expression or its `data/special_laws.json` entry, with the ranges of
  its penal articles: d.lgs. 74/2000 artt. 2-11, the legge fallimentare's 216-237, d.P.R. 380/2001 art. 44, d.lgs.
  196/2003 artt. 167-172 ...; an article led by another code -- c.c., c.p.c., c.p.p., c.p.a., Cost. -- is that
  code's whatever follows; a law's other articles are not penal: «117 TUB», «67 l. fall.», «142 codice della
  strada») -- else the article dropped and counted `charge_rito_dropped`; a bare number takes the code the text cites
  it with, else dropped. `istituto`: its frase found and its testo in the text's words. `quesiti`: each a whole
  question of the text (`question_units`: a «?» clause, with or without its lead-in before «:», or a question intake
  reads as a request or a task, also as its whole sentence) -- never a statement, never a question cut short --, else
  dropped; the kept ones in the text's order, once each. A field that fails is dropped and logged
  (`case_frame_unverified`, `frame_unverified.<field>`; a party or a question dropped counts one each, a part blanked
  `frame_unverified.<field>.<part>`).
- **Where it runs.** `intake.request_intake` (`read_frame`), before intake's rules: once per request -- the API
  (`api._request_intake`), the case-first flow (`interactive_flow.take_intake` when no intake is handed to it) and the

- **The binding.** The verified frame is the single source of client, role, rito, stage, charge or claim, institution
